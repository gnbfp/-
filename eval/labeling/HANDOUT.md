## 3. 每份怎么标

打开对应的 PDF，`Ctrl+F` 搜 **「评分」「成绩」「考核」「占总分」「评定」**，找到评分标准那一节。

**只标那一节里的评分项。** 正文里的交付要求、格式要求、字数页数、学术诚信、技术选型 —— **都不是评分点**。

一条一条抄下来，每条 4 个字段：

| 字段 | 怎么填 |
|---|---|
| `order` | 从 1 开始连续编号，按原文出现顺序。别跳号、别重复 |
| `weight` | 抄原文分值：「30 分」→ `30`；「30%」→ `30`；「满分 10 分」→ `10`。原文**没标分值** → `null` |
| `decomposable` | `true` / `false`，判据见第 4 节 |
| `label` | **你自己写的一句话标签**，不超过 12 字。**不要抄原文句子** |

**一条评分点 = 一个评分项。** 一句话里并列的几项，算几条。

---

## 4. `decomposable` 怎么判（就这三条）

| 判据 | 填什么 |
|---|---|
| 1. 它指向**一个具体交付物**，或者**已经列举了内容/子项**（A/B/C/D 小节、里程碑、清单） | `true` —— **哪怕标题读起来很虚**（"XX情况""XX质量"） |
| 2. **没有任何交付物**、只能靠主观印象打分 | `false` |
| 3. 拿不准 | `true`（默认让它拆，确认权留给群里看到原文的组长） |

**一个假例子**（这份作业书不存在，只为让你找手感）：

> 评分标准：① 报告结构完整（20 分） ② 团队协作精神（10 分） ③ 原型演示（30 分） ④ 答辩表现（40 分）

→ ① `true`（交付物 = 报告，且已列举结构子项）｜② `false`（没有交付物，只能主观印象）｜③ `true`（交付物 = 原型）｜④ **拿不准 → `true`**

## 5. 填完长什么样

空壳打开是这样：

```json
{
  "doc_id": "bim",
  "title": "BIM 技术原理及其应用课程设计",
  "source_file": "BIM 技术原理及其应用课程设.pdf",
  "scoring_section": "",
  "annotator": "",
  "annotated_at": "",
  "points": []
}
```

你填完之后（下面内容**是编的，不是答案**）：

```json
{
  "doc_id": "bim",
  "title": "BIM 技术原理及其应用课程设计",
  "source_file": "BIM 技术原理及其应用课程设.pdf",
  "scoring_section": "第二节 成绩评定",
  "annotator": "成员A",
  "annotated_at": "2026-09-13",
  "points": [
    {"order": 1, "weight": 20, "decomposable": true,  "label": "报告结构"},
    {"order": 2, "weight": 10, "decomposable": false, "label": "协作表现"}
  ]
}
```

- `scoring_section` —— 写你抄的是哪一节（原文小节标题）
- `annotator` —— 写你的**代号**（例如 `成员A`）；不要写真名，本仓库是公开的；`annotated_at` —— 写今天
- **最后一行结尾不能有逗号**

**JSON 最容易犯的 4 个错：**
1. 用了**中文引号** `“”` —— 必须全是英文双引号 `"`
2. 某一行后面**漏了逗号**
3. **最后一行多了一个逗号**
4. 整个文件最外面**少了大括号** `{ }`

推荐用 **VSCode** 打开 `填这里` 文件夹，它会自动报红。
