## 0. 架构一句话

**单进程 Python 服务。两个入口（飞书长连接 / 命令行）→ 一个前缀路由 → 五层九个模块 → JSON 落盘。**

---

## 1. 从硬性边界推出的三条架构基线

需求 `§1` 的 B1–B10 是本架构的地基，不重复。以下三条是从中推出的、会影响代码形态的结论：

1. **不引入 HTTP 服务。** B1（单进程）+ B6（命令行主链路共用同一套逻辑）⇒ 两个入口直接调用同一组模块函数。没有端口、没有 RPC、没有跨进程通信。**若将来要拆进程，必须先改 B1。**
2. **模块之间是函数调用，不是消息传递。** 同样是 B1 的直接后果。所谓"五层"是**代码分层**，不是部署单元。
3. **M8 只读文件，不 import 运行时。** B3 + B8 ⇒ 评测代码必须独立于被测代码，否则"不信 M3 自报的数"就无从谈起。

```
                    └──────┬───────┘
                           │ 调用（唯一入口）
        ┌──────────────┬───┴────┬──────────────┐
        ▼              ▼        ▼              ▼
 ┌────────────┐  ┌──────────┐ ┌────────┐ ┌──────────┐
 │intelligence│  │  collab  │ │schedule│ │  report  │
 │  M1 M2 M3  │  │  M4 M5   │ │   M6   │ │    M7    │
 └─────┬──────┘  └────┬─────┘ └───┬────┘ └────┬─────┘
       └──────────────┴───────────┴───────────┘
                      ▼
                ┌───────────┐
                │   data    │  JSON 落盘（唯一有副作用的地方）
                └───────────┘
                      ▲
                      │ 只读，单向
                ┌───────────┐
                │   eval/   │  M8（离线，不 import src/）
                └───────────┘
```

**四条硬规则：**

| 规则 | 理由 |
|---|---|
| `gateway` 是唯一能"对外说话"的层 | B5：只有它认识飞书 |
| `intelligence` / `collab` / `schedule` / `report` **不得 import `gateway`** | 它们只返回数据，不自己发消息。要发消息就把结果交回 gateway |
| `data` 是唯一有副作用的层 | 便于测试：其余模块全是纯函数 |
| `eval/` **不得 import `src/`** | B3 + B8：评测必须独立复算，不能复用被测代码的判定函数（否则等于自己改自己的卷子） |

## 5. LLM 调用点（全项目仅 3 处 —— B2）

**统一契约（三处都遵守）：**

1. 强制 JSON 输出（DeepSeek 的 `response_format: json_object`）
2. 出参过 schema 校验
3. 校验失败重试，**最多 2 次**
4. 仍失败 → 降级（M1/M3 报错给用户，M2 退回 `unknown`），**不猜**

| 模块 | 输入 | 输出 | 约束 |
|---|---|---|---|
| M1 解析 | `{ text: string }`（`§7.5` 抽取后的纯文本） | **作业元信息（课程名 / 作业标题 / 交付形式 / 截止时间）+ 评分点数组** | 每个点必须带 `quote`（原文）；模糊点标 `status=ambiguous`；元信息落 `data/assignment.json` |
| M2 方向 | **评分点清单**（`data/rubric.json`） | 2–3 个候选**选题大方向** | 标注"仅供参考、由全组拍板"；回复数字投票，过半落定；组长可直接拍板跳过 |
| M3 拆解 | 评分点数组 + few-shot 示例 | 任务卡数组 | 输出后必须过 `check()`；**LLM 不参与判定** |

## 6. 关键算法与实现位置

### 6.1 覆盖率三口径 → 两个独立实现（D-19 + B8）

| 函数 | 位置 | 分母 | 要求 |
|---|---|---|---|
| `coverage_loop()` | `src/intelligence/coverage.py` | `status=normal` 的点 | 100% |
| `balance_loop()` | `src/intelligence/coverage.py` | — | `max/min ≤ 3` |
| `coverage_gate()` | `eval/coverage.py` | **人工标注**的可拆点 | ≥80% |
| `balance_report()` | `eval/coverage.py` | — | `1−(max−min)/Σ` |

**`src/` 与 `eval/` 各写一份，不共享代码。** 这是刻意的重复——D-16 要求"不信 M3 自报的数"，共用函数就等于自己改自己的卷子。

### 6.2 M3 自检循环（D-16 / D-19）

```python
# src/intelligence/decompose.py
for round in range(2):
    failures = check(cards, rubric)
    if not failures:
        break
    cards = llm_regenerate(rubric, feedback=failures)
```

**边界处理（原待定义-31，已关闭 —— D-25）**：
- `cards` 为空 → **短路返回不达标**，不调 `max()`
- 某张卡 `effort_hours = 0` → `min_hours` 取下限 `max(min_hours(cards), 0.5)`，避免除零

判定函数本体见 `requirements.md` §7.3。

### 6.3 作业书抽取管线（D-15 / D-21）

```
文件 ──┬─ PDF  ──▶ PyMuPDF 抽正文 + find_tables() 抽表格
       ├─ Word ──▶ python-docx
       └─ 纯文本 ─▶ 直通
                    │
                    ▼
        归一化为 { text: string }
        表格块用 === 表格区域 === 分隔，每行为 "- 列名：值｜列名：值"
                    │
                    ▼
        [软校验] weight 加总 ∈ [90,110] ？否 → 附警告（不拒收）
                    │
                    ▼
                交给 M1
```

**拒收分支**：扫描版 PDF（空文本层）→ 回复"请发文字版"；图片 → 拒收（OCR 已砍，P2）。

**软校验的前置条件（原待定义-32，已关闭 —— D-25）**：仅当**全部**评分点都有 `weight`、且能归一化到百分制时才执行；有缺失、或本身非百分制（如 20 分制）→ **整体跳过，不误报**。`weight` 缺失的点也不参与均衡计算。

**表格行序列化（原待定义-33，已关闭 —— D-25）**：列内分隔符 `｜`；**每行前加 `- ` 前缀、行间用换行**，避免跨行粘连。

## 8. 四条主链路时序

### 8.1 作业书 → 任务卡 → 核对清单（命令行主链路，D-10 的门 ②）

```
CLI: 指定作业书文件
  └─▶ M1 抽取（§6.3）→ 评分点 ──▶ data/rubric.json
  │                 └─ 作业元信息 ──▶ data/assignment.json（含 deadline）
  └─▶ M3 拆解 + 自检循环（§6.2）→ 任务卡 ──▶ data/cards.json
  └─▶ M7 简版 → 命令行输出「评分点核对清单」+ 覆盖率
```

### 8.2 志愿分配

```
群: 「方向」→ M2 出候选 ──▶ 群内投票（回复数字，窗口 10 分钟）→ 过半 / 超时 / 组长拍板 即落定
群: M3 拆完 → 私聊广播「你想做哪一块」
私聊: 组员回复志愿 ──▶ data/preferences.json
截止: M4 按 submitted_at 先到先得分配
      ├─ 命中第一志愿 → source = volunteer_1
      ├─ 落选 → 第二志愿 → source = volunteer_2
      └─ 未回复 → 兜底 → source = auto（保证每人 ≥1 个任务）
      └─ 组长指定 / 改派 → source = leader（P1）
      └─▶ data/assignments.json → M7 完整版（分配总表 + 甘特图）发群
私聊: 「完成 T3」→ 写 data/assignments.json 的 completed_at（D-31）
```

### 8.3 催办（M6）

```
schedule 每天固定时间扫描 data/assignments.json
  └─ 取 data/assignment.json 的作业级 deadline 作唯一截止线（D-23）
  └─ 找出 completed_at IS NULL 且临期的任务
  └─ 两档提醒：临期 48 小时 / 24 小时（待定义-35 已关闭）
  └─▶ 交回 gateway → 群内 @负责人
  └─ 记录送达（T11 要求"有送达记录"；保留截图进演示材料）
```

- **此链路已无规格空洞**：原待定义-34（截止时间 / 完成指令）与待定义-35（阈值）均已关闭。
- 完成入口：组员私聊「`完成 T3`」→ gateway 写 `completed_at`（D-31）。**MVP 不做提交物上传。**
- **谁来叫醒 M6**：B1 单进程 ⇒ 定时器**必须在本进程内**（asyncio 定时任务或后台线程，二选一，不新增进程、不引入外部调度器）。选哪种属于实现细节，编码 M6 时定，不影响本架构。
- **成员标识从哪来**：已关闭（D-34）——靠 §8.4 的「登记」表单从 @ 结构里拿 `open_id`。本节的 @负责人、§8.2 的私聊广播都从 `data/members.json` 取人。

### 8.4 花名册登记（M0，「登记」指令 —— D-34）

```
群里: 组长发「登记」
  └─▶ gateway 回一张空白表单（模板）
组长: 照模板填 + @人 发回 ──▶ 机器人从 @ 结构里拿 open_id（不需要群成员名单权限）
  └─▶ gateway 回显规范化后的名单（谁是谁、共几人）
组长: 回「同意」 ──▶ 写 data/members.json
      └─ 回别的 / 5 分钟没回 → 作废，不动原名单
      └─ 重发「登记」→ 整体覆盖旧名单
```

- 硬规则：`组长` 有且只有一个；`组员` 至少 2 人
- 落盘后，M2 的投票分母、M4 的广播对象、M5 的组长身份、M6 的 @对象、M7 的显示名全部有据可依

### 12.3 两个入口怎么跑

```bash
# ① 飞书入口：长连接，不占端口、不需要公网
python -m src.gateway.app

# ② 命令行主链路（D5 门 ② 就是验它）
python -m src.main --file 作业书.pdf
#   → 评分点 + 任务卡 + 「评分点核对清单」+ 覆盖率

# ③ M8 评测（独立于运行时，不 import src/）
python -m eval.run --baseline data/baseline/
```

### 12.4 建议的开发顺序（与 §9 排期一致）

1. **`data/` 落盘层** —— JSON 读写。它是唯一有副作用的地方（§3），先做好，后面都好测
2. **M0 网关** —— 长连接 + 7 条指令路由（先剥 @段、再看状态、最后认前缀）+「登记」表单（§7 / §8.4）
3. **M1 解析** —— 文件 → 纯文本（§6.3）→ 作业元信息 + 评分点
4. **M3 拆解 + `check()` 自检循环**（§6.2）—— 灵魂，也是 D5 门 ③ 的主角
5. **M7 简版核对清单** —— 到这一步，D5 三条门都能验了
6. 之后依次：M2 / M4 / M5 / M6 / M7 完整版 / M8 全量

> M0 与 M3 是**并行**的两条线（前者是地基、后者是关键路径），互不阻塞。

### 12.5 常见坑

- **甘特图中文**：matplotlib 默认字体不含中文，演示会显示成方框 —— 提前配好中文字体。
- **权重加总**：作业书评分表常被抽丢行，记得开软校验（§6.3）。
- **不要**给 M4–M7 加 LLM（B2）；**不要**引入数据库、HTTP 服务或第二个进程（B1 / B4 / §1）；**不要**让 LLM 判定自己的产出（B8）；**不要**写飞书文档、申请 `docx` 权限（B7）；**不要**在 `data/` 之外落盘（D-30）。
