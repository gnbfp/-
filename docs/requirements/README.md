## 表 2 · 验收测试用例

| 编号 | 输入 / 操作 | 期望结果 |
|---|---|---|
| T01 | 机器人拉入测试群，发送任意消息 | 机器人回复指令列表（5 条），群内收发正常 |
| T02 | 群里发一份真实 C 语言课设作业书 | 产出 ≥3 张任务卡，每张含评分点溯源字段 |
| T03 | 输入含明确评分占比的作业书 | 每个评分点至少映射一张任务卡，覆盖率可复算 |
| T04 | 作业书含模糊要求（如"内容充实"） | 不硬拆，标记为"需组长确认" |
| T05 | 群里发「方向」口令 | 2–3 个候选方向 + 回复数字投票，过半落定 |
| T06 | 3 人私聊填志愿且无冲突 | 按志愿直接分配，人人有任务 |
| T07 | 2 人私聊抢同一模块 | 先到先得，后到者落入第二志愿 |
| T08 | 有人不回复志愿私聊 | 兜底分配，仍保证每人至少 1 个任务 |
| T09 | 私聊发「我想提议：...」 | 群里匿名发布，不泄露姓名；系统内部有记录 |
| T10 | 模块 A 依赖模块 B 的作业书 | 任务卡 depends_on 正确，甘特图体现先后 |
| T11 | 任务临期未标记完成 | 群内 @负责人提醒真实送达（有送达记录） |
| T12 | 全流程跑完一份作业书 | 核对清单输出，覆盖率数字与脚本复算一致 |
| T13 | 发一篇非作业书文本（如新闻） | 拒拆或要求确认，不硬拆 |
