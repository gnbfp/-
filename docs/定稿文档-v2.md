核心主张：机器人是"群里的第 N+1 个成员"。智能只押在拆解（M3），聊天是交互层不是智能点，评测集不变。
MVP 一句话：一场完整的飞书群内作业启动会——作业书进群到执行报告落群全程机器人主持，人只做两个动作：私聊填志愿、群里投票。本版为定稿版：上一版留给团队拍板的分歧点已全部拍板（见文末），直接按此开工。
1. 决策摘要
1.1 v2 变化（相对上一版评审版）
- 交互层重做：网页表单（Streamlit）整个砍掉，改为飞书群机器人——机器人即 UI，净工程量基本持平，演示价值翻倍。
- 新增两个模块：M0 机器人网关（全部操作的地基）、M5 匿名代言通道（本次转向的灵魂功能）。
- 新增流程环节：大方向共识——拆解之前先全组定方向，僵局时机器人生成候选、群投票收敛。
- 不变：任务拆解引擎与任务卡结构、评测集、执行报告三件套、D5 检查点机制。
1.2 已定项（定稿，不再讨论）
- 平台：飞书开放平台企业自建应用机器人，WebSocket 长连接接收事件，不需要公网服务器，一台学生机跑脚本即可。群消息、私聊、@提醒、交互卡片全部原生支持。
- 机器人角色边界：不提供思路、不替人写作。只做三件事——主持流程、匿名代言、发产物。方向候选是从评分点长出的脚手架，由人拍板，决策权永远在人。
- 智能范围：全项目只有 M1 解析、M2 方向候选、M3 任务拆解三处智能；其余全是规则、表单指令和模板。
- 输出物：《小组作业执行报告》发到群里 = 分配总表 + 甘特图 + 评分点核对清单。
- 演示真实性：拆解评测 15 份全真；催办真实送达；匿名代言现场真人私聊演示。
1.3 本期不做清单（Non-goals）
- QQ / 微信适配：个人机器人违反平台条款，封号风险真实存在。架构上消息接入层独立，答辩口径："QQ 没有对个人开放群机器人 API，我们选了 API 开放的飞书做 MVP，架构可移植到其他平台的官方机器人接口。"
- 自建聊天系统：账号、消息存储、会话同步等于 9 天重造一个 IM，零智能分，是陷阱。
- 自由对话理解：机器人只认 5 条固定指令，不做开放式聊天。
- 图片 OCR、模型微调、多用户并发、志愿历史记忆（同前版）。
2. 系统总览
暂时无法在飞书文档外展示此内容
交互模型：组员的全部操作只有两个入口——群里发消息（或 @机器人）和私聊机器人。机器人扮演群里的一名"项目经理"：主持流程、发布产物、@人催办、匿名代言；组员之间的自由讨论它不插话。
五层架构，投入完全不同：
- 交互层 M0：机器人网关，全部操作的地基，9/13 必须跑通。
- 智能层 M1–M3：解析、方向候选、任务拆解——全项目仅有的三处智能，M3 是灵魂。
- 协作层 M4–M5：志愿分配、匿名代言——机制全是规则，价值在社交设计，不在算法。
- 流程层 M6：催办。
- 交付层 M7 + 证据层 M8：执行报告与评测集。
数据流：作业书（群里发文件）→ 评分点清单 → 候选方向 → 任务卡数组 → 私聊志愿 → 分配结果 → 执行报告。每一步的中间产物都是人可读的 JSON 文件，方便调试，也方便演示时拆开讲。
3. 模块规格
3.1 M0 机器人网关（交互层 · P0 · 地基）
职责：机器人进群，收发消息，把消息路由到对应模块。
实现：飞书开放平台创建企业自建应用（免费）→ 启用机器人能力 → 订阅消息事件（WebSocket 长连接模式，无需公网服务器）→ 官方 SDK（lark-oapi）写事件处理循环。
指令集（MVP 全部指令，就这 5 条，前缀固定不做自然语言理解）：

验收：T01。
3.2 M1 输入解析（智能层 · P0）
职责：把老师下发的作业书变成机器可用的结构化输入。
输入：组长在群里或私聊发作业书文件（文字版 / PDF 文本版，PDF 用 PyMuPDF 抽取文本，不做 OCR）。
输出：结构化 JSON——课程名、作业标题、交付形式、截止时间，以及核心的评分点清单（每条含编号、原文引用、分值或权重、可观察要求），以群消息形式发出来全员可见。
实现：单次 LLM 调用，JSON schema 约束输出，程序校验必填字段。无法解析的模糊要求（如"内容充实"）标记"需组长确认"，不硬猜。
验收：T02–T04。
3.3 M2 方向共识（智能层 · P0 简版）
职责：拆解之前先定大方向——解决"作业第一晚就卡在选题"的真实痛点。
流程：组员先在群里自由讨论（机器人不插话）；无人提案或讨论不收敛时，任何人发「方向」触发——机器人基于评分点清单生成 2–3 个候选大方向发到群里，明确标注"仅供参考，由全组拍板"→ 组员回复数字投票 → 过半即落定。组长已有方向时直接拍板跳过本环节。
边界：候选方向从作业书评分点长出来，是"读懂作业书"的智能延伸，不是替人思考；机器人平时不提供任何思路。
验收：T05。
3.4 M3 任务拆解（智能层 · P0 · 灵魂）
职责：评分点清单 → N 张任务卡，满足三个硬约束：评分点全覆盖、工作量尽量均衡、依赖顺序合理。全项目的灵魂，智能全部押在这里。
任务卡数据结构：
字段
类型
说明

string
T1、T2……全局唯一
module_name
string
模块名，动词开头（如"实现登录模块"）
rubric_refs
array
必填，溯源字段：对应评分点编号 + 原文引用。演示时评委看的就是它——证明 agent 真读懂了作业书

array

这块交什么：一个源文件 / 一段报告章节 / 一页 PPT

string
怎么算做完，从对应评分点原文改写，可被核对清单复用
实现三步（手写"规划—执行—反思"循环，不用框架）：
1. 生成：LLM + few-shot。放 2–3 份人工精拆范例进 prompt——这是整个项目最值得花时间打磨的资产。
2. 自检：程序化检查两项——每个评分点是否被至少一张任务卡覆盖（遍历 rubric_refs）；最大与最小模块工作量之比是否超过阈值（初始参数 3 倍，待校准）。不满足则把检查结果喂回 LLM 重拆，最多 2 轮。
3. 输出：任务卡数组 + 覆盖率数字，以群消息卡片逐张发到群里。
为什么不用微调：数据不够（只有 15 份任务书）、时间不够（9 天）、坏了查不出原因。prompt 方案每次改动立刻能跑评测集验证，调优回路短得多。
验收：T06–T08、T13。
3.5 M4 志愿分配（协作层 · P0）
职责：任务卡数组 + 组员志愿 → 人人有活的分配结果。表单已砍，私聊指令代替：机器人私聊每个组员"你想做哪一块？"附任务卡列表，回复序号即可——私聊填报比公开表单社交压力更低，"羞于自评"的设计在私聊通道里最完整。
分配规则（按顺序执行，纯代码）：
1. 无人冲突 → 按志愿直接分配。
2. 多人填同一模块 → 先到先得（按私聊消息时间戳），落选者进入其第二志愿。
3. 无人填的模块 → 从未填表者中按剩余工作量均衡兜底分配。
4. 硬约束：人人至少 1 个任务——"不存在一个人包揽"的机制保证。
边界：组长强制指定、改派为 P1。冲突仲裁不引入智能，规则透明可解释本身就是卖点。
验收：T06–T08。
3.6 M5 匿名代言（协作层 · P0 尾部 · 可第一个牺牲）
职责：让"有想法但羞于开口"的组员有出口——本次转向的灵魂功能。私聊发「我想提议：…」→ 机器人在群里发布"有组员提议：……"，不署名。
防滥用：系统内部记录提交者（组长可查询，P1）；内容原样转达，不修改、不总结、不加工。
地位说明：价值高但不是链路必需环——工程成本只有半天（与志愿指令同构：私聊输入 → 群消息输出）。若 M3 进度落后，它第一个被砍，时间让给拆解。智能永远优先于社交功能。
验收：T09。
3.7 M6 催办（流程层 · P1）
职责：让拖延可见。每天固定时间扫描各任务 deadline；临期 48 小时、24 小时两档，在群里 @负责人，真实送达（保留截图进演示材料）。已完成任务由组员私聊「完成 T3」标记，MVP 不做提交物上传。
验收：T11。
3.8 M7 执行报告（交付层 · P0 简版 / P1 完整版）
职责：把前面所有产物装配成一页纸，直接发到群里——"输出某个东西"的最终答案。
三件套：
1. 分配总表：谁、干什么、依据哪个评分点、截止时间。
2. 甘特图：matplotlib 绘制，模块时间条 + 依赖箭头 + 截止线。
3. 评分点核对清单：每个评分点 → 对应任务 → 负责人 → 完成勾选。
实现：python-docx 输出或 HTML 转 PDF，模板固定，不做花哨 dashboard。
验收：T12。
3.9 M8 评测集（证据层 · P0）
职责：量化证明 M3 拆得比人拆好——全项目可信度的来源，也是"可验收成果"评分项的硬通货。
构成：15 份真实作业书（每人从自己上过的课里收 5 份，尽量覆盖文 / 理 / 工科）；人工基线（三人分别手拆再互评统一，作为对照组）。
指标定义（公式先行，当前值待采集，不虚构基线）：
- 评分点覆盖率 = 任务卡覆盖的评分点数 ÷ 人工标注评分点总数
- 工作量均衡度 = 1 −（最大模块工时 − 最小模块工时）÷ 全部模块工时合计
输出：human vs agent 对比表，进演示材料。80% 覆盖率目标是初始参数，首次实测后校准，不写成承诺。

9. 演示剧本（5 分钟 · 真实群直播）
1. 开场 30 秒：痛点场景——"上个小组作业谁在做？一个人。这个机器人解决的就是这件事。"
2. 输入 1 分钟：组长在群里发真实作业书 → 机器人回评分点清单。
3. 方向 30 秒：「方向」口令 → 候选方向 + 现场投票收敛。
4. 拆解 1.5 分钟（核心）：任务卡逐张过，重点展示评分点溯源字段；放 human vs agent 对比表。
5. 协作 1 分钟：两名队友现场私聊填志愿（一人故意不填）、第三人私聊匿名提议 → 群里公布分配结果 + 匿名发布。
